# Firebird Match

Firebird Match подбирает подрядчиков для мероприятия по датасету организаторов Firebird #79-lite (трек 06 «Креативные индустрии»). Каталог содержит 66 профилей. Приложение не бронирует услуги и не отправляет заявки.

## Как устроен подбор

Пользователь → форма Streamlit → короткий одноинструментальный вызов модели → `recommend_contractors` → `catalog.recommend()` и CSV → выбор ID выдержки из профиля → проверка ссылки на выдержку Python → карточки.

**Python** проверяет запрос, город, категорию, busy_dates, бюджет, формат, язык и длительность, затем выбирает и сортирует карточки по начальной цене и ID. Это порядок по цене, не оценка качества. **AI** не выбирает подрядчиков и не пишет факты: он получает только выбранные карточки и их короткие выдержки, затем возвращает `{id, evidence_id}`. Python проверяет, что каждый ID выбран ровно один раз и выдержка принадлежит именно этому профилю, после чего формирует факты и объяснение. Описание профиля — недоверенный текст и не исполняется как инструкция. Это ограниченный tool-calling workflow, не свободно планирующая multi-agent система.

## Установка (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Используются Python standard library, Streamlit и официальный OpenAI Python SDK. `.env.example` только показывает имя переменной и **не загружается автоматически**. `.env` не нужен и исключён из Git. Для AI ключ берётся из `OPENAI_API_KEY` в текущем процессе или вводится скрыто через `getpass`:

```powershell
.\.venv\Scripts\python.exe run_local.py --web --ask-key
.\.venv\Scripts\python.exe run_local.py --check-ai --ask-key
```

Если ключ уже задан в окружении, уберите `--ask-key`. `run_local.py --web` привязывает Streamlit к `127.0.0.1`. `run_local.py --check-ai` делает один настоящий сквозной запуск, печатает модель, число API/tool calls, ID и объяснения, и возвращает ненулевой код, если сработал fallback. `--help` не требует ключа и не делает запросов.

По умолчанию используется `gpt-4.1-mini`; при необходимости модель можно переопределить переменной окружения текущего процесса `OPENAI_MODEL`. Сетевые повторы отключены. Два API вызова используют общий бюджет ожидания около 9 секунд; клиентские таймауты не гарантируют строгую верхнюю границу времени выполнения.

## Offline проверки

Без ключа приложение показывает локальные объяснения с подписью «AI недоступен; показан локальный результат». Если подходящих карточек нет, API не вызывается и это явно указывается. Fake client используется только в offline unit tests и не считается проверкой OpenAI API.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe cli.py --demo
.\.venv\Scripts\python.exe run_local.py --help
```

## Результаты и ограничения

Статусы: `MATCHED`, `NO_CATEGORY_IN_CITY`, `NO_MATCH`. При 1–2 карточках показываются размер категории и реальные причины исключения. Счётчики причин могут пересекаться, поэтому их нельзя складывать как количество профилей.

Дата поддерживается только с 2026-09-23 по 2026-12-31. Отсутствие даты в `busy_dates` означает лишь «по календарю датасета не занят», а не подтверждённую бронь. Цена указана «от» и не равна итоговой смете. Карточки помечают синтетические профили и оценочные цены/города. Выдержка из описания атрибутируется профилю и не является независимо проверенным фактом.

**Live API status:** в этой среде ключ отсутствует, поэтому настоящий API-run не выполнен. Offline запуск не подтверждает, что AI часть доступна для проверки жюри; разрешённый экспертам live-доступ следует обеспечить по правилам конкурса, не добавляя credentials в репозиторий. Облачная публикация не выполняется.
